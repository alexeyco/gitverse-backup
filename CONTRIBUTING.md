# Contributing

## Branch names

Use the prefix that matches the change type, followed by a short lowercase
kebab-case description:

- `feat/<kebab-desc>` for a feature.
- `fix/<kebab-desc>` for a bug fix.
- `chore/<kebab-desc>` for maintenance.

For example, use `feat/yandex-disk-backup` for the Yandex Disk backup feature.

## Changes and documentation

Keep changes focused. Use the OpenSpec change artifacts in `openspec/changes/`
to guide implementation when a change has a plan. Write user-facing
documentation in English.
